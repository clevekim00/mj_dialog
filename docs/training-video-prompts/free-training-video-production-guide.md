## 1. 결론과 무료의 범위

**추천 경로는 AI가 운동별 Blender 또는 2D 애니메이션 코드를 작성하고, 로컬 무료 도구가 그 코드를 렌더링하는 방식이다.** 외부에서 보이는 입술·혀끝 동작은 2D 벡터/Canvas, 입천장·어금니 등 내부 접촉은 Blender의 2D 단면 또는 제어 가능한 3D 모형을 우선 검토한다. 기존 캐릭터와 동작의 일관성을 확인한 뒤 확장한다.

이는 **생성형 영상 모델이 프레임을 직접 생성하는 방식과 다르다.** AI가 코드를 작성하더라도 Blender/Canvas의 결과는 좌표·키프레임·보간에 따라 렌더링된다. AI 작성 코드 역시 해부학적 정확성을 보장하지 않으므로 사람이 수정하고 임상 전문가가 검수한다.

| 경로 | 무료 여부·비용 조건 | 장점 | 제약·판단 |
|---|---|---|---|
| AI 작성 Blender 코드 → 로컬 렌더링 | Blender는 무료 오픈소스. 코드 작성 AI 서비스/API 요금은 별도일 수 있음 | 혀·입술·치아 접촉과 유지 시간을 명시적으로 제어, 소스 재현 가능 | 모델링·리깅·수정 시간 필요. 3D는 렌더 비용과 캐릭터 스타일 맞춤 부담 |
| AI 작성 Flutter Canvas/SVG 또는 TypeScript 2D 코드 → 프레임 → MP4 | 로컬 렌더 도구와 FFmpeg 등의 무료 도구 사용 가능. AI와 추가 도구 이용 조건은 별도 | 단순 운동을 적은 자원으로 반복 제작, 시간·좌우 방향 제어 용이 | 기존 프로젝트에 완성된 운동 렌더러나 내보내기 기능이 있는 것은 아님. 새 제작 도구 구현 필요 |
| 로컬 생성형 영상 모델 → 직접 프레임 생성 | 모델 라이선스가 허용하면 구독 없이 실행 가능. 장비·저장 공간·전기·작업 시간 필요 | 기준 이미지 기반 후보 제작 가능 | 혀 중복, 접촉 오류, 치아 변형, 캐릭터 흔들림. 정확한 혀 동작 보장 불가. 주 제작 경로로 권장하지 않음 |
| 클라우드 AI 영상 서비스의 무료 체험·크레딧 | 수량·해상도·기간·상업 이용·워터마크 조건에 제한 가능 | 설치 없이 후보 확인 가능 | **지속 무료가 아님.** 크레딧 소진 후 비용 발생 가능. 현재 특정 서비스의 무료량을 보장하지 않음 |

무료 로컬 도구는 무제한 무료 AI 서비스나 무료 노동 시간을 뜻하지 않는다. 모든 시각 콘텐츠와 동작을 AI 도움으로 새로 제작하되, 기존 캐릭터 자산의 이용 권한과 전문가 검수를 별도로 확보한다. 유료 Higgsfield 구독은 이 추천 경로의 필수 조건이 아니다.

## 4. 공통 사전 설계

### 2026-10-27 사용자 피드백 반영: 얼굴 전체의 연동

앞으로 얼굴 시범 영상은 중립·목표 입 모양·복귀의 **얼굴 전체 자세**를 먼저 설계한다. 입술과 함께 운동에 필요한 턱·볼·입꼬리·턱선 변화를 일관된 리그 또는 연속된 자세로 연결한다. 카메라와 머리 위치를 안정적으로 유지하는 것과 턱을 고정하는 것은 구분한다. 혀 독립 운동처럼 턱 안정이 필요한 경우는 해당 운동 의도를 따른다.

정지 얼굴 위에 질감이 다른 입 도형만 얹고 폭·높이만 바꾸는 방식은 후속 제작에 사용하지 않는다. 피부·입술의 선화, 명암, 질감과 치아의 가림을 얼굴 전체에서 맞춘다. 주요 자세뿐 아니라 중간 프레임과 느린 재생에서 접합부·얼굴 정체성·턱과 볼의 연동을 확인한 후 MP4 후보를 만든다.

`lip_03_a_to_i/v001`은 입만 교체한 방식이 어색하다는 사용자 피드백을 받은 참고 초안이다. 후속 영상의 제작 템플릿이나 승인본으로 사용하지 않는다.

1. 아직 파일이 없는 운동 하나를 선택한다. 카탈로그의 ID·지시문·자막·길이·안전 등급을 복사해 작업 카드로 만든다.
2. AI에 기존 캐릭터, 해당 공통·운동별 프롬프트와 함께 **좌표/키프레임으로 제어 가능한 소스**를 요청한다. 서비스에 이미지를 전송하는 행위는 별도 승인된 제작 단계에서만 한다.
3. 중립·첫 접촉·유지·반대 접촉·복귀의 정지 자세를 먼저 설계한다. 좌우를 시청자 기준으로 할지 대상자 기준으로 할지 작업 카드에 기록하고 앱 지시와 대조한다. 임의 미러링을 금한다.
4. 전문가가 접촉 위치와 운동 의도를 확인한 다음 보간을 추가한다. 입술 가림, 치아 관통, 구강 단면 왜곡이 생기면 소스 좌표나 리그를 수정한다.
5. 현재 플레이어 큐는 진행률 0–15% 준비, 15–45% 따라 하기, 45–65% 유지, 65–90% 복귀, 90–100% 휴식이다. 일반 운동은 이에 맞춘다. 좌우 교대·다음 음절 미리 보기는 과거 명세의 모든 설계가 현재 구현된 것으로 가정하지 말고 실기기에서 확인한다.

예시 AI 작업 지시:

```text
기존 캐릭터를 유지한 16:9 무음 교육 애니메이션의 소스를 작성하라.
운동 ID: tongue_02_touch_lips, 길이: 5초.
혀끝이 윗입술에 접촉하고 중앙으로 돌아온 뒤 아랫입술에 접촉하고 중립으로 복귀한다.
머리와 턱을 고정하고 혀끝 좌표, 접촉 대상, 유지 시간을 독립 변수로 둔다.
입술·치아·혀를 분리하고 frameIndex/fps로 시간을 결정한다.
중립·각 접촉·복귀 프레임을 검토할 수 있게 하라.
글자·음성·UI·워터마크를 넣지 말고 임상 정확성을 주장하지 말라.
패키지 설치, 네트워크 호출, 업로드, 기존 자산 덮어쓰기를 수행하지 말라.
```

5초에 양방향 접촉이 불명확하면 속도를 무리하게 올리지 않는다. 전문가와 길이를 재검토하고 4–8초 안에서 결정하며, 후속 코드 작업에서 `loopDuration`도 맞춘다.

## 5. 경로 A: AI 작성 Blender 소스의 로컬 렌더링

1. AI에 Blender Python 소스 작성을 요청한다. 카메라·배경·레이어·재질·혀 경로·프레임 범위를 명시한다. 처음에는 2D 평면 레이어/직교 카메라로 기존 스타일을 맞추고, 내부 운동에 필요한 경우에만 3D를 사용한다.
2. 입술, 윗니/아랫니, 혀끝/혀몸통, 경구개/연구개, 볼을 별도 요소로 구성한다. 3D에서는 shape key 또는 뼈대를 사용하고 접촉 위치를 고정한다. AI가 만든 모형을 해부학적으로 정확하다고 가정하지 않는다.
3. 30fps·5초 예시는 프레임 1–150이다. 끝은 중립으로 돌아오게 하되 중립 프레임을 과도하게 중복해 정지감이 생기지 않도록 한다. 유지가 필요한 운동을 단순 왕복 사인파로 대체하지 않는다.
4. 초안의 주요 자세와 저해상도 미리보기를 검토한 뒤 원본 해상도로 PNG 시퀀스를 출력한다. 중간 실패 시 프레임부터 재개할 수 있도록 바로 MP4만 출력하는 것보다 시퀀스를 우선한다.
5. `.blend`, 생성에 사용한 `.py`, 도구 버전, 설정·시드(사용 시), 프롬프트, 검토 기록을 보관한다. AI 코드의 파일 삭제·외부 호출·설치 명령을 검토한 뒤 별도 승인하에 실행한다.
6. PNG를 공통 내보내기 절차로 MP4로 변환한다. 복잡한 광원·실사 재질보다 동작의 가독성과 스타일 일치를 우선한다.

공식 근거: [Blender 애니메이션 출력](https://docs.blender.org/manual/en/latest/render/output/animation.html), [출력 설정](https://docs.blender.org/manual/en/latest/render/output/properties/output.html), [영상 형식](https://docs.blender.org/manual/en/latest/files/media/video_formats.html). 애니메이션 출력과 형식은 공식 검색 결과로 확인했으나 일부 본문 열기는 실패했다. 실제 제작 때 설치 버전의 메뉴를 대조한다.

## 6. 경로 B: AI 작성 2D 코드의 프레임 출력

### Flutter Canvas/SVG

1. 기존 플레이어를 녹화하지 않고 별도의 제작용 화면/도구를 설계한다. 현재 앱 변경은 후속 승인 대상이다.
2. AI가 `CustomPainter`의 `Path`와 좌표로 입술·혀·치아를 그리게 하거나, 편집 가능한 SVG 레이어를 만들게 한다. 얼굴 전체 자세를 기준으로 구강·턱·볼·입꼬리의 연동을 설계하고, 몸·배경과 분리한다. 정지 얼굴에 입 도형만 교체하는 방식은 사용하지 않는다. SVG를 Flutter에서 쓰려면 렌더링 의존성 필요 여부부터 확인한다.
3. 운동 ID별로 목표 자세와 접촉 좌표를 정의한다. 각 프레임의 시간 `t = frameIndex / fps`를 직접 넣어 같은 프레임이 재현되게 한다. 실시간 타이머나 화면 녹화 속도에 의존하지 않는다.
4. 영상 영역만 `RepaintBoundary`로 감싸고 실제 paint 완료 후 `toImage`로 PNG를 얻는다. 캐릭터 이미지와 폰트가 준비됐는지 확인하고 UI·자막은 포함하지 않는다.
5. 프레임을 한 장씩 저장하고 이미지 메모리를 해제한다. `toImage`는 MP4 인코더가 아니므로 별도 FFmpeg 등의 변환이 필요하다. 1080p 수백 장을 메모리에 한꺼번에 쌓지 않는다.

근거: [CustomPainter](https://api.flutter.dev/flutter/rendering/CustomPainter-class.html), [RenderRepaintBoundary.toImage](https://api.flutter.dev/flutter/rendering/RenderRepaintBoundary/toImage.html).

### TypeScript + Canvas/SVG

1. AI에 브라우저에서 실행되는 별도 제작 도구를 작성하게 한다. 저장소에 완성된 도구가 있다고 가정하지 않는다. 구독 없이 렌더링할 수 있어도 개발 시간과 AI 요금은 들 수 있다.
2. `renderFrame(frameIndex, fps)`에 따라 Canvas/SVG를 갱신하고 고정 크기로 출력한다. CSS 실시간 애니메이션이나 `requestAnimationFrame` 경과 시간을 영상 시간의 기준으로 쓰지 않는다.
3. Canvas의 PNG 출력 또는 Playwright 스크린샷으로 운동 영역만 저장한다. 이미지 로딩 완료와 프레임 갱신 완료를 기다리고 기기 배율·뷰포트를 고정한다. Playwright가 필요하면 설치는 별도 승인 후 진행한다.
4. PNG를 MP4로 변환한다. 브라우저의 MediaRecorder 기본 코덱이 앱 배포 규격의 H.264 MP4라고 가정하지 않는다.

근거: [Playwright 스크린샷](https://playwright.dev/docs/screenshots). 이 API는 프레임 캡처 수단이며 운동 타임라인/해부학 모델은 별도 구현 사항이다.

## 7. 경로 C: AI 영상 모델로 직접 생성

로컬 모델 또는 무료 크레딧 서비스에 기준 이미지와 기존 프롬프트를 넣어 후보를 만드는 방식이다. 로컬 UI가 무료여도 모델별 이용·재배포·상업 이용 조건은 따로 확인한다. 클라우드 서비스/API의 요금, 워터마크, 다운로드·저작권 조건도 생성 전에 확인한다.

ComfyUI는 실행 환경이고 그 자체가 하나의 영상 생성 모델은 아니다. Apple Silicon/MPS 지원 여부와 특정 영상 모델의 실행 가능성은 다른 문제다. GPU 또는 통합 메모리, 모델 크기, 프레임 수, 해상도, 정밀도와 연산 지원에 따라 실행 불가·메모리 부족·매우 긴 생성 시간이 생길 수 있다. CPU 실행은 특히 느릴 수 있다. 이 Mac의 모델별 적합성·속도는 벤치마크하지 않았으며 특정 메모리 용량만으로 실행을 보장하지 않는다.

후보를 얻더라도 혀끝의 접촉 위치, 혀 뒤쪽 움직임, 좌우 교대, 치아·입술 형태와 마지막 중립 자세를 프레임별로 검사한다. 반복 생성으로 정확성이 확보된다고 보지 않는다. 오류가 계속되면 경로 A/B로 전환한다. 특히 내부 접촉·저항 운동·음절의 생리적 차이는 생성형 영상만으로 검증할 수 없다.

근거: [ComfyUI 공식 하드웨어·운영체제 요건](https://docs.comfy.org/installation/system_requirements). 현재 문서는 운영체제와 가속 지원의 근거이며 특정 영상 모델의 최소 메모리나 임상 품질 근거가 아니다.

## 8. 공통 내보내기·파일명·소스 보관

아래는 **향후 승인된 제작 단계에서 사용할 예시이며 이번 문서 작업에서 실행하지 않는다.** FFmpeg/ffprobe가 준비되어 있고 입력 프레임 검수가 끝났다는 전제다. 도구가 없으면 자동 설치하지 않는다. GUI 대안인 [Shotcut](https://www.shotcut.org/)도 무료 오픈소스이며 [공식 FAQ](https://www.shotcut.org/FAQ/)에서 내보내기와 상업 이용 조건을 확인할 수 있다. 프로젝트 저장과 영상 내보내기는 별개다.

작업 디렉터리 제안:

```text
<승인받은 로컬 원본 보관소>/<운동ID>/v001/
  source/        # .blend/.py/.dart/.ts/.svg와 사용 이미지
  frames/        # frame_0001.png ...
  exports/       # <운동ID>_v001_review.mp4
  review/        # 주요 프레임, 메타데이터, 권리·전문가 검수 기록
```

원본은 대용량·민감 자료를 포함할 수 있으므로 앱 assets에 모두 넣거나 자동 업로드하지 않는다. 위치·백업 정책을 정한 로컬 보관소에 남긴다. 승인본 파일과 원본 버전·SHA-256을 대응시켜 재제작이 가능하게 한다.

30fps·5초·150개 프레임의 예시(셸의 현재 위치는 위 버전 디렉터리):

```sh
ffmpeg -n -framerate 30 -start_number 1 -i frames/frame_%04d.png \
  -frames:v 150 -vf "scale=1280:720:flags=lanczos,setsar=1" \
  -c:v libx264 -crf 20 -pix_fmt yuv420p -r 30 -an \
  -movflags +faststart exports/tongue_02_touch_lips_v001_review.mp4
```

`-n`은 기존 출력 파일이 있으면 중단한다. 프레임 수·fps는 선택한 운동 길이에 맞춰 바꾸고 16:9 원본만 입력한다. 단순 스케일로 얼굴 비율이 왜곡되지 않도록 한다. 마스터의 동작을 임의로 자르거나 역재생해 루프를 만들지 않는다. 실제 오디오 제거는 음량 0과 다르다.

```sh
ffprobe -v error -show_entries \
  stream=codec_type,codec_name,width,height,pix_fmt,r_frame_rate,avg_frame_rate:format=duration,size \
  -of json exports/tongue_02_touch_lips_v001_review.mp4
```

영상 스트림 1개, 오디오 스트림 0개, H.264, 1280×720, yuv420p, 결정한 fps, 운동별 길이인지 확인한다. 길이만 4–8초라고 합격시키지 말고 유지 시간과 동작 완료 여부를 확인한다. 압축에 따른 혀 경계 뭉개짐도 확인한다. 명세의 전체 60MB 기준을 넘으면 별도 배포 방식을 검토하되 이번 작업에서 원격 manifest나 업로드를 도입하지 않는다.

근거: [FFmpeg 공식 명령 옵션](https://ffmpeg.org/ffmpeg.html), [ffprobe 공식 검사 옵션](https://ffmpeg.org/ffprobe.html).

- [ ] 임상 전문가가 운동 의도·접촉 위치·주의 문구를 검토하고 이름/역할·날짜·소스 버전을 기록했다.

AI 작성/검토와 기술 검사를 통과했다는 사실을 임상 승인으로 대체하지 않는다. 전문가는 단순히 영상이 보기 좋은지뿐 아니라 해당 운동을 이 앱 대상자에게 어떻게 안내할지 확인해야 한다.

## 10. 승인 후 앱 연결과 최종 검수 절차

아래는 후속 구현 계획이며 이번 문서 변경에 포함되지 않는다.

1. 기존 8개와 동일 이름의 파일이 없는지 확인한다. 승인된 **새 운동**만 `assets/videos/training/<운동ID>.mp4`에 복사하고 기존 자산은 덮어쓰지 않는다. 후보 버전은 앱 폴더 밖에 남긴다.
2. 카탈로그의 해당 `_exercise`에 `video: 'assets/videos/training/<운동ID>.mp4'`를 추가하고 실제 길이에 맞춰 `seconds`를 검토한다. 교호는 `_alternating` 헬퍼가 현재 `video`를 받지 않으므로 후속 구현에서 선택적 영상 매핑을 설계해야 한다. `_sustainedVowel`은 영상 인자를 받는다.
3. `pubspec.yaml`의 기존 `assets/videos/training/` 등록을 확인한다. 앱에 포함되지 않은 새 하위 디렉터리나 과거 계획 경로로 임의 이동하지 않는다.
4. `safetyTier`, 안전 문구, 전문가 전용 제한을 보존한다. 관리자 훈련 열기/닫기는 임상 승인과 별개다.
5. 후속 변경 범위에 맞춰 기존 `test/guided_training_catalog_test.dart`, `test/guided_training_player_screen_test.dart` 등을 실행한다. 테스트 통과는 영상 내용의 정확성을 보장하지 않는다.
6. iOS·Android에서 새 자산 로딩, 검은 화면/비율, 느린 재생, 반복 경계, 반복 횟수, 일시정지·재개·백그라운드 복귀, 자막·TTS와 동작 타이밍을 검사한다. 마지막 약 80ms 전에 완료를 감지하는 현 구현 때문에 핵심 동작을 맨 마지막에 배치하지 않는다.
7. 파일 누락/재생 실패 시 안내 화면으로 복귀하는 동작과 안내 문구를 확인한다. 실패 대체 화면을 실제 시범 영상처럼 설명하지 않는다.
8. 승인된 파일·연결·검수 기록만 별도 리뷰한다. 커밋·푸시·배포는 추가 지시가 있을 때 진행한다.

## 11. 저작권·원본 관리와 완료 기준

기존 캐릭터와 AI 입력/출력 이미지, 모델, 재질·폰트·샘플 코드의 이용 조건을 확인한다. 무료 도구 사용이 외부 자산의 재배포 권리를 자동 부여하지 않는다. 실존 인물 얼굴·목소리를 참조하거나 닮게 만드는 경우 해당 인물의 동의와 사용 범위를 확인한다. AI 생성이라는 이유로 초상권 문제가 사라지는 것으로 보지 않는다.

YouTube 등 참고 자료는 운동 의미를 이해하는 참조로만 사용한다. 화면 캡처·다운로드·프레임 추출·음성·자막 복제·무단 트레이싱·재업로드를 제작 경로로 삼지 않는다. 자료를 AI에 입력할 때도 입력 권한과 서비스 약관을 확인한다.

프롬프트, AI/모델·도구 버전, 생성 코드, 레이어 자산, 원본 프레임, 내보내기 설정, 라이선스·동의 근거, 기술·임상 검수 결과를 원본과 함께 보관한다. 기준을 통과하지 못한 후보는 앱에 연결하지 않는다. 최종 완료는 **새 파일 보존·기술 규격·동작 정확성·전문가 검토·앱 실기기 확인**이 모두 끝난 상태다. 이 문서를 저장한 것은 영상 제작이나 임상 승인 완료를 뜻하지 않는다.
