# mj-dialog 자체 서버 없는 아키텍처 구현 계획

[한국어](server-free-architecture-plan.md) | [English](server-free-architecture-plan.en.md)

작성일: 2026-10-11 · 상태: 구현 계획 · 코드 확인 기준: 2026-10-10

현재 Flutter 앱을 유지하면서 기본 학습과 기록을 오프라인으로 제공한다. AI는 선택 설치하는 온디바이스 모델로 제공하고, 콘텐츠는 서명 검증 후 갱신하며, 기기 이전은 QR 페어링을 통한 암호화 직접 전송으로 구현한다. 기존 React MVP와 GPT-4o 구상은 초기 배경이며, 구현 기준은 현재 말이음·SpeechBridge 저장소다.

이 계획의 완료 기준은 앞으로 수행할 검증 항목이다. 아래의 기존 구현이 모바일 배포판에서 모두 검증되었다는 의미는 아니다.

## 목표와 범위

- 기본 레슨·단어·문장·학습 기록을 네트워크와 AI 없이 사용할 수 있게 한다.
- 생체인증 또는 기기 잠금으로 앱을 열고, 플랫폼에 보호된 키로 로컬 데이터를 보호한다.
- 사용자 기록과 녹음·영상을 암호화해 로컬에 저장한다.
- 모델과 콘텐츠는 사용자가 선택해 설치하며, 파일 가져오기를 유지한다.
- 자동 클라우드 동기화, 중앙 계정 서버, GPT-4o 수준의 클라우드 응답, 블록체인은 범위에서 제외한다.
- IPFS/libp2p는 선택적 배포 경로다. 기본 기능의 실행 조건으로 삼지 않는다.

자체 백엔드를 운영하지 않는 것과 외부 인프라를 전혀 사용하지 않는 것은 다르다. 선택 다운로드에는 정적 호스팅이나 배포 피어가 필요하며, 가용성과 트래픽 비용은 별도 관리 대상이다. 데이터 동기화를 추가하지 않아도 OS 자동 백업은 발생할 수 있으므로 백업 제외 정책도 구현한다.

## 현재 저장소와 재사용 범위

| 영역 | 현재 구현 | 필요한 변화 |
|---|---|---|
| 앱 | Flutter, Dart SDK `^3.10.4`, Riverpod | 기존 화면과 상태 관리 유지 |
| 기능 | 대화, 문장·자음 훈련, 게임, 기록, 설정 | 레슨 진도와 개인 단어장 모델을 명시적으로 정의 |
| AI | `flutter_gemma`, Gemma 2B asset 설치 | 선택 설치와 기기별 실행 판정으로 분리 |
| iOS AI | 시작 충돌을 이유로 코드에서 비활성화 | 네이티브 등록·추론 실기기 검증 후 활성화 |
| 모델 자산 | 약 1.3GB 파일이 앱 asset에 등록 | 기본 배포에서 제외, 검증된 외부 파일 설치 |
| 기록 | SharedPreferences, 일반 SQLite, 별도 미디어 파일 | 공통 저장 계층과 암호화, 기존 데이터 이관 |
| 음성 | OS STT/TTS, 네이티브 채널, 녹음·재생 | 오프라인 지원 판정과 실패 대체 흐름 |
| 업데이트 | Ed25519 서명, SHA-256, 버전 비교, 이전 팩 복구 | 파일 입력, 모델 팩, 키 교체, 설치 중단 복구 강화 |
| 서버 | FastAPI 분석 서버, Kotlin/Spring 추론 예제 | 서버 없는 배포에서 호출·상태 조회·재시도 제외 |

현재 제품은 말하기 재활 연습 앱이다. 일반 언어 학습의 레슨·단어장을 기존 훈련과 동일한 기능으로 간주하지 않는다. 기존 연습 흐름을 유지하고 필요한 학습 모델을 추가한다. 텍스트 일치도, 로컬 신호 측정, 생성형 대화는 실제 발음 정확도나 치료 효과 평가와 계속 구분한다.

## 권장 모듈

아래 경로는 추가 또는 개편 제안이다. 화면은 기능별 repository를 호출하고, repository가 저장소·AI·콘텐츠 서비스와 네이티브 어댑터를 사용한다. 화면이 키를 직접 읽거나 다운로드 파일을 바로 활성화하지 않도록 한다.

| 모듈 | 위치 | 책임 |
|---|---|---|
| 실행 정책 | `lib/services/runtime/` | 서버 없는 배포 정책, 네트워크 허용 범위, 기능 가용성 |
| 앱 잠금과 키 | `lib/services/security/` | 잠금 해제, 기기 키, 데이터 키 보호, 백그라운드 잠금 |
| 암호화 저장 | `lib/services/storage/` | DB·미디어 암호화, 마이그레이션, 복구 |
| 학습 데이터 | 기존 기능별 repository | 레슨·단어장·진도·기록 접근 |
| 로컬 AI | `lib/services/ai/` | 대화 엔진, 모델 관리, 기기 지원 판정 |
| 음성 | 기존 `lib/services/audio/` | 로컬 STT/TTS 판정, 녹음·재생, 대체 입력 |
| 콘텐츠 | 기존 `lib/services/resources/` | 서명·호환성·해시 검증, 설치·활성화·복구 |
| 기기 이전 | `lib/services/transfer/` | QR 페어링, 전송 세션, 가져오기 검증 |
| 배포 도구 | `tools/content_release/` | 팩 제작, 매니페스트 생성·서명·검증 |

## 앱 잠금과 암호화 저장

앱 잠금, 기기 식별 키, 데이터 암호화 키를 분리한다. 생체인증이나 기기 암호는 로컬 접근을 허용하고, 기기 키는 페어링한 상대에게 키 소유를 증명한다. 중앙 계정이나 실명 인증을 의미하지 않는다. DB·미디어에는 별도 난수 데이터 키를 사용한다.

iOS는 Secure Enclave의 P-256 키와 접근 제어된 Keychain을 조합한다. Secure Enclave를 임의의 DB 비밀번호 저장소로 취급하지 않는다. Android는 Keystore 기반 키 보호를 사용하며, 하드웨어 보호 수준과 지원 여부를 검사한다. 생체인증 성공 화면만으로 보호를 끝내지 않고 실제 키 사용에 접근 제어를 연결한다.

SQLCipher 기반 DB를 우선 검토하되 현재 `sqlite3`와 네이티브 연결의 호환성을 검증한 후 라이브러리를 확정한다. 일반 SQLite의 `secure_delete`는 암호화가 아니다. 녹음·영상에는 별도의 인증된 암호화를 적용하고 임시 평문, WAL, 캐시, 공유 파일, OS 백업까지 저장 수명주기에 포함한다.

기존 기록 이관은 다음 순서로 수행한다.

1. 기존 SharedPreferences·SQLite·미디어와 스키마 버전을 조사한다.
2. 암호화 저장소를 생성하고 UUID와 관계를 보존하며 복사한다.
3. 레코드 수, 미디어 해시, 참조 무결성을 검증한다.
4. 완료 표식을 기록하고 새 저장소로 전환한다.
5. 검증된 전환 후 기존 평문을 정리한다. 중단 시 재개할 수 있게 한다.

플래시 저장장치에서 과거 평문의 물리적 완전 삭제를 보장한다고 표현하지 않는다. 잠금 변경·키 무효화·기기 분실 시의 복구 정책을 정의하고, 별도 내보내기가 없는 기기 분실은 복구할 수 없음을 안내한다.

## 온디바이스 AI와 음성

`AiService`를 `ConversationEngine`, `ModelManager`, `DeviceCapabilityService`로 분리한다. 기존 텍스트 비교는 LLM 없이 계속 제공한다. 모델 상태는 미설치·다운로드 중·검증 중·사용 가능·미지원·실패를 구분하며 설치 실패가 기본 연습을 막지 않게 한다.

모델은 한국어·영어 품질, 최대 메모리, 지연, 발열, 파일 형식, 런타임 호환성, 재배포 라이선스로 선정한다. 특정 모델이나 패키지 버전은 실기기 검증 후 확정한다. iOS에서는 현재 비활성화 원인을 해결하기 전 AI 지원을 표시하지 않는다.

LLM, STT, TTS는 별도 기능이다. 현재 STT 경로는 온디바이스 전용 인식을 강제하지 않으므로 Flutter와 iOS 네이티브 경로를 함께 정비한다. 로컬 지원이 없으면 원격 인식으로 자동 전환하지 않고 직접 입력·녹음·수동 완료를 제공한다. TTS도 로컬 음성 설치 상태를 검사하며, 필수 예시는 배포 권리가 확보된 내장 음원을 사용할 수 있다.

## 서명된 모델과 콘텐츠 업데이트

기존 `ResourceCatalogRepository`, `ResourceSignatureVerifier`, `ResourcePackManager`를 확장한다. 파일·HTTPS·선택적 IPFS는 같은 검증 파이프라인에 연결한다. 매니페스트 공개키는 앱에 신뢰 기준으로 포함하고, 배포 서명 개인키는 앱과 저장소에 넣지 않는다.

필드 제안은 `schemaVersion`, `packId`, `version`, `minAppVersion`, `sizeBytes`, `sha256`, 선택적 `cid`, `mirrors`, `keyId`, `signature`다. 모델에는 런타임·파일 형식·언어·라이선스를 추가한다. 서명 대상 바이트의 정규화 규칙을 제작 도구와 앱에서 동일하게 정의한다.

설치 순서는 다음과 같다.

1. 신뢰 공개키로 매니페스트 서명을 확인한다.
2. 스키마·앱 호환성·버전·용량 한도를 확인한다.
3. 임시 파일로 다운로드하거나 가져온다.
4. 크기와 SHA-256, 콘텐츠 형식과 경로 안전성을 확인한다.
5. 검증된 버전을 활성화하고 이전 정상 버전을 보존한다.

대형 모델은 전체 바이트를 메모리에 받는 기존 방식 대신 스트리밍 다운로드·해시 검증으로 처리한다. 설치 중 강제 종료를 고려해 파일과 메타데이터가 일관되게 복구되도록 한다. 키 교체, 허용된 복구, 수신 버전의 하향 설치 방지를 구분하고 악의적 재전송과 정상 복구를 혼동하지 않는다.

CID는 콘텐츠 주소이며 서명자를 증명하지 않는다. IPFS 파일 구성에 따라 CID와 원본 파일 SHA-256이 다를 수 있으므로 각각 관리한다. 완전 오프라인에서는 최신 버전이나 키 폐기 사실을 즉시 알 수 없다. 업데이트 확인 실패·만료만으로 기본 레슨을 막지 않는다.

## QR 기기 이전

첫 구현은 동일 Wi-Fi 또는 핫스팟에 연결된 두 기기가 앱을 전경에서 실행하는 조건으로 제한한다. QR 자체가 인터넷 NAT를 통과시키는 것은 아니다. 연결할 수 없을 때는 암호화 파일 내보내기·가져오기를 제공한다.

QR에는 기록이나 개인키 대신 일회용 세션 ID, 연결 정보, 공개키 지문·페어링 정보를 넣는다. 검증된 키 교환 프로토콜과 양쪽 확인 코드를 사용하고, 세션 만료·재사용 방지·암호화 전송을 적용한다. 암호 프로토콜을 자체 설계하지 않는다.

DB 파일을 그대로 복사하기보다 버전이 있는 논리적 기록 형식과 미디어 목록을 전송한다. 수신 기기는 새 키를 만들고 데이터를 재암호화한다. 하드웨어 개인키를 이전하지 않는다. 임시 영역에서 해시·스키마·참조 관계를 검사하고 UUID로 중복을 판정한 후 트랜잭션으로 반영한다. 초기 버전에서는 빈 프로필로의 이전을 우선하고, 기존 데이터와 충돌하는 경우 자동 덮어쓰기 대신 명시적 정책을 적용한다.

수신 검증과 사용자 확인 전 원본을 삭제하지 않는다. 취소·중단 시 부분 반영을 막고, 보관용 암호화 파일의 복구 비밀은 기기 키와 독립적으로 다룬다. 기기 이전은 자동 동기화가 아니다.

## 단계별 실행 계획

| 단계 | 구현 범위 | 완료 기준 |
|---|---|---|
| 1 오프라인 MVP | 기본 학습, 서버 호출 제외, 앱 잠금, 암호화 저장과 이관 | 첫 실행·재실행 비행기 모드에서 연습·저장·재생·삭제 가능, 이관 중단 복구 |
| 2 온디바이스 AI | 번들 모델 제외, 선택 설치·삭제, iOS 실행 문제 해결, 기기 검사 | 모델 없이 핵심 기능 정상, 설치 모델은 오프라인 실행, 미지원·메모리 부족 시 안전한 대체 |
| 3 서명 콘텐츠 업데이트 | 파일 입력, 공통 매니페스트, 키 교체, 복구 정책 | 변조·미서명·비호환 팩 거부, 설치 중단 후 기존 콘텐츠 사용 |
| 4 QR 기기 이전 | 동일 LAN 페어링, 암호화 전송, 검증 후 반영 | iOS↔Android, 중단·취소·중복 가져오기 대응, 확인 전 원본 보존 |
| 5 선택적 P2P | IPFS 어댑터, 필요 시 libp2p 실험 | P2P·게이트웨이 실패 시에도 내장 콘텐츠와 파일 입력 정상 |

**선행 의존성:** 2단계 모델 다운로드부터 서명 검증이 필수다. 3단계의 최소 검증기·신뢰 공개키·안전한 설치 절차를 2단계에 앞당기고, 3단계에서 콘텐츠 전체로 확장한다. 1단계에서는 앱 패키지에 포함된 콘텐츠를 기본 신뢰 경로로 사용한다.

## 우선 작업과 검증

- [ ] 서버 없는 배포 정책을 추가하고 분석 버튼·요청·상태 조회·재시도·기존 원격 작업 삭제 경로를 정리한다.
- [ ] 저장소 어댑터와 키 수명주기를 정의하고 SQLite·SharedPreferences·녹음 이관을 구현한다.
- [ ] 모델 asset과 선택 설치를 분리하고 최소 서명 검증을 연결한다.
- [ ] Flutter와 네이티브 음성 경로에서 오프라인 기능을 판정한다.
- [ ] 기존 리소스 테스트에 변조·버전 재전송·키 교체·중단 복구·용량 제한을 추가한다.
- [ ] 기록 이관, 키 무효화, 저장 공간 부족, 전화·백그라운드 전환을 실기기로 확인한다.
- [ ] QR 이전의 위조·재사용·단절·중복·수신 실패를 검증한다.

소프트웨어 단위 테스트와 별개로 iOS·Android 배포판의 최초 실행, 네트워크 요청 여부, 메모리·발열·설치 용량을 확인한다. P2P에는 개인 기록을 게시하지 않고 공개 콘텐츠만 배포한다. 일정 산정과 최종 패키지 선정은 암호화 저장소 및 iOS 추론 기술 검증 후 진행한다.
