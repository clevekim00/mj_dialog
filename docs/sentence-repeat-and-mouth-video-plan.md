## 1. 목적

사용자가 1-2문장 단위로 말하기 연습을 한 뒤, 녹음된 자기 목소리를 바로 확인하고, 같은 문장을 여러 번 다시 읽으며 변화 과정을 비교할 수 있게 한다. 이후 단계에서는 자유대화/문장 연습 중 전면 카메라로 입모양 영상을 촬영해 발음과 입 움직임을 함께 복습할 수 있게 한다.

사진 메모에서 정리한 핵심 흐름은 다음과 같다.

```text
문장 연습
→ 녹음 완료
→ 끝에서 다시 읽어보기
→ 재녹음 후 다시 확인
→ 발음이 불명확한 단어/문장 반복
→ 입모양 영상까지 함께 확인
```

## 2. 기능 범위

### 2.1 1차 구현: 반복/재녹음

현재 앱 구조에서 바로 구현 가능한 범위다.

- 문장 연습 결과 화면에서 `방금 녹음 듣기` 제공
- 같은 문장을 다시 녹음한 경우 `이전 녹음 듣기` 제공
- `같은 문장 반복` 버튼으로 현재 문장을 유지한 채 재녹음
- 낮은 점수 또는 재시도 횟수를 기반으로 반복 연습 후보 식별
- 녹음 기록 화면에서 기존 `다시 연습` 버튼으로 같은 문장 재진입

### 2.2 2차 구현: 어려운 문장/단어 반복 진입

기존 `PracticeSession`의 `score`, `retryCount`, `contentId`, `targetText`, `audioFilePath`를 활용한다.

- 70점 미만 기록을 `다시 연습 추천`으로 분류
- 같은 `contentId` 또는 같은 `targetText`를 기준으로 반복 횟수 표시
- 오늘의 연습 홈에서 어려운 문장 카드를 노출하고 반복 연습 진입
- 이전 최고 점수와 현재 점수 비교
- 낮은 점수의 단어를 단어 게임/복습 모드로 연결

### 2.3 3차 구현: 입모양 영상 촬영

별도 패키지와 권한이 필요한 기능이며 2026-06-19 기준 1차 범위를 구현했다.

필요 패키지:

```yaml
camera: ^0.12.0+1
video_player: ^2.11.1
```

iOS 권한:

```xml
<key>NSCameraUsageDescription</key>
<string>Speech Rehab uses the camera to record mouth movement during speech practice.</string>
```

Android 권한:

```xml
<uses-permission android:name="android.permission.CAMERA" />
```

권장 흐름:

- 연습 화면에 `입모양 촬영` 토글 추가
- 녹음 시작 시 전면 카메라 무음 영상도 함께 녹화
- 연습 완료 후 `내 목소리 듣기`와 `입모양 영상 보기` 제공
- 녹음 파일과 영상 파일을 같은 `PracticeSession.videoFilePath`에 연결

현재 범위:

- 전면 카메라로 무음 영상 저장
- 연습 직후 하단 시트에서 영상 재생
- 연습 화면에서 촬영 전/중 전면 카메라 프리뷰 표시
- 녹음 보관함에서 과거 세션의 입모양 영상 재생
- 자유대화 화면에서 입모양 촬영 토글, 전면 프리뷰, 마지막 영상 보기 제공
- 자유대화 사용자 메시지에 `mouthVideoPath` 저장
- 세션 삭제 시 연결된 영상 파일 삭제

후속 개선:

- 자유대화 히스토리 목록에서 과거 입모양 영상 다시 열기
- 영상 기반 입술/입 벌림 정도 자동 분석
- 영상 파일 용량 관리와 오래된 영상 정리 정책

## 4. 구현 순서

1. 결과 화면에서 방금 녹음과 이전 녹음을 나란히 들을 수 있게 한다.
2. 같은 문장 반복 버튼을 명확히 유지하고 재녹음 UX를 개선한다.
3. 녹음 기록 화면의 `다시 연습`을 반복 연습 진입점으로 유지한다.
4. 어려운 문장/단어 반복 진입 카드를 오늘의 연습 홈에 추가한다.
5. 전면 카메라 촬영 권한/서비스를 추가한다.
6. 녹음과 영상 저장 경로를 하나의 세션 기록으로 묶는다.
7. 결과 화면에서 음성 재생과 입모양 영상 재생을 제공한다.

## 7. 내 문장 두 번 읽기 — 제품 기획 (2026-10-02)

**상태: 2026-10-02 구현 완료 범위는 10절을 참조한다.** 이 절 이후는 앞의 과거 계획보다 우선한다. 기존 70점 미만 자동 추천·최고 점수 경쟁은 이 기능에 적용하지 않는다. 대상은 성인 후천성 마비말장애 사용자의 자가훈련이다.

### 7.1 목표와 기본 결정

생활에 필요한 문장을 직접 입력하거나 사진에서 가져와 읽고, 두 녹음과 각각의 AI 피드백을 문장별로 보관한다. 성공은 높은 점수보다 연습 수행·자기청취·편안함 확인으로 정의한다.

- 메뉴: `훈련 → 문장 말하기 → 내 문장 두 번 읽기`. 기록에는 `내 문장` 필터와 문장별 보관함을 둔다. 상위 메뉴를 늘리지 않는다.
- 기본 가정: 문장 1개 → 날짜별 연습 묶음 여러 개 → 묶음당 최대 2개 녹음 → 녹음당 하나의 평가 상태/결과. 사용자의 보관 정책 답변에 따라 확정한다.
- 1차만 녹음해도 저장·종료할 수 있다. 2차는 선택이며 미완료를 실패로 표시하지 않는다.
- 두 녹음이 저장된 묶음에서 다시 연습하면 새 묶음을 만든다. 예전 녹음은 자동 덮어쓰기하지 않는다.
- AI는 녹음별로 처리한다. 평가를 기다리지 않고 듣기·두 번째 녹음·종료할 수 있다.
- 기본 가정: 녹음과 재생은 오프라인, AI는 명시적 전송 동의 후 서버에서 처리. 이 문서는 전송 동의 자체가 아니다.
- 지원 언어는 한국어와 영어. 화면 언어와 읽을 문장의 언어를 별도로 선택한다.

### 7.2 사용자 흐름과 화면

```text
내 문장 목록 → 직접 입력 / 사진에서 가져오기
→ 텍스트 검토·수정 → 문장 나누기·선택 → 저장
→ 선택: 편안하게 준비하기 → 1차 녹음 → 듣기 / AI 피드백 보기
→ 선택: 한 가지 연습 목표 → 2차 녹음 → A/B 비교
→ 문장별 기록 → 날짜별 녹음 쌍 → 각각 재생·평가 확인
```

| 화면 | 주요 요소와 동작 |
|---|---|
| 내 문장 | 제목·문장 미리보기·최근 날짜·연습 묶음 수, 검색, 추가 |
| 입력·OCR 확인 | 직접 입력/붙여넣기, 이미지 선택 또는 지원 기기 촬영, 자르기·회전, 원본/추출문 대조, 수정·문장 분리·합치기 |
| 읽기 | 큰 문장, 사용자가 표시한 쉼 위치, 선택적 예시 듣기, 1차/2차 상태, 파형 표시, 하단 고정 녹음/중지 |
| 두 녹음 비교 | 1차 듣기·2차 듣기·순서대로 듣기, 각각 시간·파형·평가 상태, 자기 느낌, 오늘 마치기 |
| 문장별 기록 | 날짜 내림차순 묶음, 1차만 저장 표시, AI 대기/완료/분석 어려움, 이전 묶음과 비교 |

파형은 기존 기본 켜짐을 유지하되 숨길 수 있다. 파형 높이를 목소리의 좋고 나쁨으로 해석하지 않는다. 피드백은 자동 팝업 없이 접힌 카드로 제공하고 원할 때 연다. 녹음 중 입력·문장 변경·재생을 막고 녹음/중지 버튼은 항상 보인다. 최대 녹음 120초는 기존 캡처의 기술 상한이며 오래 말하기 목표가 아니다.

A/B는 한 번에 한 파일만 재생한다. `순서대로 듣기`는 A → 짧은 간격 → B, 반복은 기본 끔. 기본은 원음·동일 재생 배율이며 자동 음량 보정은 하지 않는다. 두 파형은 동일 시간/진폭 눈금으로 제시한다. 다른 마이크·입력 게인·처리 설정에서는 음량 차이를 향상으로 판단하지 않는다. 편집한 문장 버전 간 비교는 청취만 허용하고 수치 증감은 숨긴다.

### 7.3 문장 입력과 OCR

- 이미지 1장 최대 10MB/20메가픽셀. 문장 개수·문장당 글자 수·전체 입력 글자 수의 제품 제한은 해제했다.
- 문장 분리는 제안일 뿐이다. 줄바꿈·약어·숫자·따옴표로 잘못 나뉜 부분을 사용자가 합치거나 나눈 후 확정한다. 긴 문장은 의미 단위로 나누도록 제안한다.
- OCR 결과는 녹음 전에 반드시 확인한다. 읽기 순서·한국어 띄어쓰기·흐린 글씨·손글씨 오류를 검토할 수 있게 한다. 혼합 언어는 수동 선택/분리하도록 안내한다.
- 사진 속 이름·진료내용 등 불필요한 정보는 잘라내거나 수정할 수 있다. 원본 사진은 기본 보관하지 않으며 텍스트 확정/취소 후 임시 사본을 삭제한다. 사용자 사진 보관함의 원본은 건드리지 않는다.
- `TextExtractionService` 인터페이스: 지원 여부/언어 조회, 이미지 인식, 취소, 임시 파일 정리. 모든 플랫폼에 텍스트 입력 대체 경로를 둔다.
- macOS/iOS: Apple Vision 어댑터 후보. OS에서 지원하는 인식 언어를 조회하고 한국어·영어 실기기 검증 후 노출한다. Android: ML Kit 한국어/라틴 문자 모델 후보, 모델 설치 상태를 표시한다. Windows/Linux: 별도 로컬 OCR 엔진 어댑터의 정확도·배포·라이선스 검토가 필요하다. 미지원 기기는 텍스트 입력을 제공하며 몰래 클라우드 OCR로 전환하지 않는다.
- 웹/데스크톱 지원을 모바일 Flutter 래퍼 패키지 하나로 보장한다고 가정하지 않는다. OCR 공급자와 패키지는 구현 전 PoC로 확정한다. 근거: [Apple Vision](https://developer.apple.com/documentation/vision/recognizing-text-in-images), [ML Kit Text Recognition v2](https://developers.google.com/ml-kit/vision/text-recognition/v2).

## 8. AI 평가·기록·서버 설계

### 8.1 평가 의미와 출력 계약

화면 명칭은 `AI 연습 피드백`. 진단, 장애 중증도, 감정/긴장도 추정, 검증되지 않은 발음 정확도 총점은 제공하지 않는다. 음성 인식이 잘 안 된 것을 사용자의 발음 실패로 단정하지 않는다. 마비말장애의 ASR 성능에는 변동이 보고되어 있다. [ASR 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC6909999/)

평가 순서:

1. 실제 오디오 존재·해독·길이·무음·클리핑·잡음 등 분석 가능성 확인.
2. 목표 문장을 답으로 강제하지 않는 ASR 전사. 목표문장 정렬은 별도로 수행하고 두 결과를 혼동하지 않는다.
3. 전사와 문장 비교는 `인식된 텍스트의 차이`로 표시. 한국어는 문자, 영어는 단어 기반 등 언어별 정규화 버전을 기록한다. 누락/삽입/치환은 인식 오류일 수도 있음을 함께 표시한다.
4. 실제 측정값에 근거한 발화 길이·쉼·선택적 구간 정렬을 제공. 느림/짧음/큰 소리를 일률적으로 더 좋다고 하지 않는다.
5. 제한된 구조화 관찰값으로 AI가 짧은 설명과 다음 시도 제안 한 가지를 만든다. 원문에 포함된 지시문은 데이터로 취급하고 실행하지 않는다. 생성 결과는 스키마와 근거 연결을 검증하고 실패 시 정해진 안내 문구로 대체한다.

`Assessment` 필드: `id, recordingId, audioSha256, sentenceRevisionId, status, language, analysisVersion, modelVersion, promptVersion, createdAt, transcript?, qualityFlags[], observations[{kind,value,unit,evidenceStartMs?,evidenceEndMs?}], nextPracticeTip?, unavailableReason?, score:null`.

상태: `notRequested → queued → running → completed | unavailable | failed | cancelled | expired`. 유효한 분석이 없는 상태는 점수 0이 아니다. 확률이 검증되지 않았다면 confidence 퍼센트를 만들지 않는다. 사용자 전사 수정은 별도 주석으로 보관하고 원래 AI 결과를 바꾸지 않는다.

녹음마다 평가 레코드 하나를 만들고 그 상태를 갱신한다. 같은 파일의 실패 재시도는 같은 평가 ID를 사용한다. 완료한 결과는 자동 재평가하지 않고 모델 버전을 고정해 보존한다. 한 쌍은 같은 파이프라인 버전을 요청하며 버전이 다르면 변화 판정을 생략한다. 두 결과가 모두 준비될 때만 비교 관찰을 계산한다. 별도의 세 번째 AI 평가를 만들 필요는 없다.

### 8.2 데이터 모델과 저장 규칙

| 엔터티 | 핵심 필드/제약 |
|---|---|
| Sentence | UUID, title, language, source(text/ocr), createdAt, currentRevisionId |
| SentenceRevision | UUID, sentenceId, confirmedText, speechLanguage, textHash, createdAt; 녹음 이후 불변 |
| PracticePair | UUID, sentenceRevisionId, startedAt, localDate, timezoneOffset, status(draft/oneTake/twoTakes), optional tensionBefore/After, optional fatigue, chosenGoal |
| Recording | UUID, pairId, slot(A/B), relativeAudioPath, audioSha256, durationMs, format, sampleRate, device/processingMetadata, interrupted; UNIQUE(pairId,slot) |
| Assessment | UUID, recordingId UNIQUE, 위 평가 계약, remoteJobId? |

관계: Sentence 1:N Revision 1:N PracticePair 1:최대2 Recording 1:1 Assessment. 미요청 평가도 상태 레코드는 존재한다. 제목 변경은 내용 버전을 바꾸지 않고 문장 내용/언어 변경은 새 Revision을 만든다. 동일 문장 입력 시 기존 문장을 제안하되 자동 병합하지 않는다.

새 저장소는 트랜잭션을 지원하는 로컬 SQLite를 권장한다. 실제 Dart 드라이버는 지원 OS 시험 후 확정한다. 오디오 파일은 앱 전용 디렉터리에 UUID로 저장한다. 임시 녹음 → 완전한 파일로 이동 → DB 연결의 저널을 남기고 시작 시 미완료 저장을 복구한다. 저장 공간 부족 때 성공 메시지를 내지 않으며 재시도 전까지 확보된 임시 음성을 유지한다. 두 슬롯이 완성된 뒤에는 새 연습 쌍을 만든다.

문장 삭제는 하위 버전·묶음·녹음·평가와 서버 대기 작업까지 범위를 미리 표시한다. 실제 파일/DB/서버 삭제가 모두 완료되기 전까지 재시도 가능한 삭제 대기 상태를 둔다. 로컬 삭제 이후 도착한 서버 결과가 기록을 되살리지 않도록 tombstone을 둔다. 사용자 원본 사진은 삭제 대상이 아니다. 외부 공유는 명시적인 선택 시에만 제공한다.

기존 기록은 별도 어댑터로 읽고 원본을 보존한다. 문자열만 같은 기존 녹음들을 임의로 A/B 한 쌍으로 변환하지 않는다. `RehabRecordIndex`에 새 `sentencePair` 종류를 추가하고 연습 횟수는 평가 수가 아니라 실제 녹음 수로 집계한다.

### 8.3 API 설계 — 현재 구현은 10절 참조

기존 `/v1/analysis/jobs`는 목표 음소/위치를 필수로 받는 API라 자유 문장 평가에 그대로 사용하지 않는다. 기존 인증·업로드 제한·작업 조회 구조를 재사용하되 별도 계약으로 확장한다.

| 메서드·경로 | 계약 |
|---|---|
| GET `/v1/sentence-analysis/capabilities` | 언어, 분석 버전, 120초/파일 한도, 제공 지표, 보관 정책 버전·기간, 서비스 상태 |
| POST `/v1/sentence-analysis/jobs` | multipart audio + recordingId, assessmentId, sentenceRevisionId, confirmedText, language, audioSha256, analysisVersion, consentPolicyVersion; `Idempotency-Key`; 202 jobId/status/expiresAt |
| GET `/v1/sentence-analysis/jobs/{jobId}` | 소유자 전용 상태 및 위 Assessment 결과 |
| DELETE `/v1/sentence-analysis/jobs/{jobId}` | 취소·임시 음성/결과 삭제, 반복 요청 안전; 실행 중 작업은 삭제 확정 전 cancelling 응답 |

예시 요청: `recordingId=rA, assessmentId=eA, sentenceRevisionId=s1v1, language=ko-KR, confirmedText=물을 한 잔 주세요., analysisVersion=sentence-v1`. 반환 결과는 요청 식별자·해시·문장 버전이 모두 일치할 때만 로컬 기록에 연결한다. 해시는 업로드 파일로 서버가 재계산한다.

401/403 인증·소유권, 409 동일 키의 다른 본문/버전 불일치, 413 크기 초과, 422 언어·문장·오디오 검증, 429 제한, 503 분석 준비 안 됨. 자동 재시도는 일시 네트워크 오류/429/503에 한정해 지수 백오프하고, 인증 문제는 사용자 조치로 분리한다. 앱 종료 뒤 재개 시 작업 ID를 조회하고 만료 시 사용자에게 다시 분석 선택을 준다.

기록의 원본은 로컬이며 MVP에 서버 문장 CRUD/기기 간 동기화를 넣지 않는다. 서버 작업은 영속 큐·소유권·멱등성·삭제 확인이 필요하다. 운영 인증 발급, 문장 ASR/관찰/피드백 파이프라인, 큐와 삭제 처리는 신규 구현 대상이다. 기존 서버의 메모리 작업/짧은 TTL 구조만으로 장기 히스토리를 보장하지 않는다.

개인정보 기본안: 업로드 전에 전송 항목(문장·오디오), 수신 서버/AI 공급자, 목적, 보관 기간을 표시한다. 원본 OCR 이미지는 분석 서버에 보내지 않는다. 서버 임시 오디오는 작업 종료/취소 후 제거하고 장애 시 24시간 이내 청소, 결과는 수신 확인 후 삭제·최대 24시간 만료를 목표로 한다. 이는 현재 서버 보장 사항이 아니며 운영 검증 전 확정하지 않는다. 원문·오디오를 로그에 남기지 않고 모델 학습에 사용하지 않는다. 외부 AI 공급자의 보관·학습 정책도 출시 전에 확인한다.

### 8.4 현재 기반과 개발 단계

2026-10-02 소스 확인: `PracticeCapture`는 하나의 PCM 입력으로 파형과 WAV 녹음을 제공하며 16kHz/최대120초를 사용한다. `PracticeSession`은 목표 문장·녹음·피드백·평가 방식/버전을 보관한다. `RehabRecordIndex`는 여러 저장소의 기록을 합친다. 현재 발음 서버는 MFA 정렬을 제공하고 검증 전 practiceScore/gop는 null이다. OCR 의존성과 이번 문장/쌍 모델은 없다. 기존 graphify 그래프는 스크립트 위주여서 이 기능 관계를 찾지 못했으며 최신 소스에서 직접 확인했다.

1. 로컬 핵심: 텍스트 입력·버전·두 슬롯 녹음·A/B·문장별 기록·삭제 복구·통합 기록 어댑터.
2. OCR: macOS/iOS·Android 어댑터 PoC, 수정 화면, 모델/권한/미지원 대체 경로. Windows/Linux는 별도 통과 조건.
3. AI: 동의 UI, 인증/영속 작업, 품질·전사·관찰값, 근거 기반 피드백, 멱등 재시도와 삭제, 언어별 검증.
4. 편안한 연습: 아래 준비 루틴·선택적 자기보고·피드백 숨김, 사용자/언어재활사 사용성 검토.

출시 완료 조건: A/B 뒤바뀜 0건, 저장/재시작 후 파일·문장·평가 연결 일치, 1차만 종료 가능, OCR 수정 전 녹음 불가, 무음/잡음에 임의 점수 없음, 취소·오프라인·삭제 후 늦은 응답 처리, 큰 글씨에서 고정 조작부 접근 가능, KO/EN 전체 동등 동작. 분석 검증은 언어·마비말장애 유형/중증도·기기별 대표 표본과 전문가 평가로 수행하며 검증 전 수치형 발음 정확도를 출시하지 않는다.

## 9. 말하기 긴장을 낮추는 방법 — 조사와 제품 적용

조사일: 2026-10-02. 심리적 불안, 후두/턱의 과도한 힘, 신경학적 근긴장은 서로 같지 않다. 앱은 원인을 진단하거나 목소리로 긴장도 점수를 만들지 않는다.

| 방법 | 근거와 적용 범위 | 앱에서의 적용 제안 |
|---|---|---|
| 편안한 호흡 | NHS는 억지로 깊게 들이마시지 않는 부드러운 호흡을 안내한다. 일반 스트레스 대처 근거이며 마비말장애 치료 효과의 직접 증거는 아니다. | 준비 화면에서 몇 차례 편한 호흡, 건너뛰기 제공. 숨 참기·최대 들숨·발성 시간 경쟁 제외. |
| 불필요한 힘 풀기 | ASHA 음성장애 자료는 과도한 발성 노력에서 이완 기법을 다룬다. 모든 마비말장애 유형에 같은 기법이 적합한 것은 아니다. | 어깨·손의 힘을 편안히 놓기 안내. 목 누르기/후두 마사지/강한 근육 수축은 자동 자가훈련에 넣지 않음. |
| 단계적으로 말하기 상황 넓히기 | NICE 사회불안 지침은 개별 CBT와 단계적 노출을 권고한다. 마비말장애 전용 앱 효과와는 구분한다. | 혼자 짧은 말 → 혼자 문장 → 신뢰하는 사람 앞 → 원하는 실제 상황. 단계 선택·중단은 사용자에게 맡김. |
| 말의 부담 조절 | ASHA 성인 마비말장애 지침은 개인별 말하기·호흡/발성 전략과 참여를 다룬다. 구체적 방법은 평가에 따라 달라진다. | 짧은 의미 단위, 사용자가 쉼 위치 선택, 필요할 때 휴식. 일률적인 속도/음량 목표 제외. |
| 주의·피드백 부담 줄이기 | 불안 지침을 참고한 제품 가설이다. 이 앱에서 긴장이 줄어드는 효과는 아직 검증되지 않았다. | 실시간 점수/순위 없음, 결과 펼치기 선택, 다음 시도 목표 한 가지, 건너뛰기·한 번만 녹음 허용. |

선택형 `편안하게 준비하기` 약 1–2분: (1) 편한 자세 잡기와 힘 놓기, (2) 자연스러운 호흡 몇 차례, (3) 짧은 구절을 편하게 연습, (4) 준비되면 녹음. 이 시간은 UI 설계 제안이지 임상적으로 검증된 처방 용량이 아니다. 준비 과정을 수행해야 녹음할 수 있도록 강제하지 않는다.

긴장 자기보고는 선택형 0–10(0=전혀 긴장되지 않음, 10=매우 긴장됨) 및 `건너뛰기`. 묶음 전후에만 물으며 생체 측정이나 진단 척도로 표현하지 않는다. 전후 차이가 이 루틴의 치료 효과를 입증한다고 표시하지 않는다. 본인이 더 편하게 느낀 녹음을 선택할 수 있으며 AI 결과와 다르더라도 그대로 보관한다.

어지러움·통증·호흡곤란이 생기면 연습을 멈추고 편히 쉰다. 지속적인 힘든 발성은 언어재활사/의료진과 조정하고, 말하기 회피·불안이 일상을 크게 제한하면 정신건강 전문가의 평가/CBT 상담을 고려한다. 심리적 불안을 신경학적 말장애의 원인이라고 단정하지 않는다.

### 앱 사용 흐름

1. **훈련 → 긴장 낮추기**에서 말하기 전, 자음·단어, 문장, 일상 대화, 발성, 구강·호흡, MPT, 게임 안내를 선택한다. 각 훈련 상단의 긴장 낮추기 버튼은 해당 상황을 먼저 펼친다. 녹음·측정 중에는 방해하지 않는다.
2. **훈련 → 문장으로 말하기 → 내 문장 두 번 읽기**에서 문장을 직접 입력하거나 사진을 선택한다. 사진은 영역 자르기·90도 회전 후 기기에서 OCR한다. 한국어/영어와 글을 확인해야 저장할 수 있다. 한 줄에 한 문장으로 저장하며 문장 개수·문장당 글자 수·전체 입력 글자 수 제한은 없다. 빈 입력은 저장하지 않는다.
3. 문장을 열고 새 연습을 시작한다. 1차 녹음 후 듣고, 원하면 2차를 녹음한다. **두 파일을 각각 듣거나 차례로 비교**하며, 파형은 기본 표시하고 숨길 수 있다. 녹음은 최대 120초이고 화면 하단 조작부는 고정한다.
4. 녹음별 **동의 후 AI 분석**을 선택한다. 서버·전송 항목·보관 기간을 확인한 뒤 문장과 해당 음성만 보낸다. 사진은 보내지 않는다. 평가 한 건은 한 녹음에 연결되며 재시도해도 새 평가를 중복 생성하지 않는다.
5. 문장별로 날짜가 다른 녹음 쌍과 평가를 다시 연다. 기록 메뉴에도 문장 연습이 표시된다. 두 번째 녹음은 선택이며, 새 연습은 기존 파일을 덮어쓰지 않는다. 선택적으로 연습 전후 긴장 정도(0–10)를 직접 기록한다. AI는 긴장을 판정하지 않는다.

### 저장 및 오류 처리

- 앱 지원 폴더의 `sentence_practice/history.sqlite`와 UUID WAV 파일을 사용한다. 저장 저널·임시 파일 이름 변경·SHA-256·SQLite 트랜잭션으로 실패 시 복구하며, 열리지 않는 한 파일 때문에 전체 기록을 막지 않는다.
- 문장 본문은 녹음과 함께 고정된다. 수정한 문장은 **새 문장으로 추가**한다. 문장 버전 그룹 편집·즐겨찾기·기기 간 동기화는 아직 없다.
- 서버가 없어도 입력·녹음·재생·기록을 사용할 수 있다. 분석 실패/취소/만료는 녹음을 삭제하지 않는다. 작업 ID를 저장해 다시 조회할 수 있다. 자동 무한 재시도 대신 사용자가 재시도한다.
- 서버 작업이 남아 있으면 먼저 각 녹음의 ‘서버 작업 정리’를 완료한 뒤 문장을 삭제한다. 로컬 삭제 표식은 늦게 도착한 결과가 기록을 되살리지 못하게 한다. 백업/OS 저장장치의 물리적 삭제까지 보장하지는 않는다.

### AI와 서버의 실제 수준

`/v1/sentence-analysis/capabilities`, `POST /jobs`, `GET /jobs/{jobId}`, `DELETE /jobs/{jobId}`를 구현했다. 기존 음소 MFA API와 별도이다. 설치한 **faster-whisper** 모델로 목표 문장을 힌트로 주지 않고 인식한 뒤 녹음 길이·저에너지 구간 수·목표 글과 인식 글의 차이를 반환한다. 다음 연습 안내는 정해진 문구이며 자유 생성 LLM 평가가 아니다. 조용한 구간 수는 호흡 능력이나 말 명료도의 측정치가 아니다. `score`는 항상 `null`이다. 무음·너무 작은 소리·심한 클리핑은 분석 불가로 처리한다.

SQLite 영속 큐, 재시작 복구, 소유자 인증, 멱등성, 파일 해시·PCM 검증, 제한된 작업 수, 취소 후 결과 재생성 차단을 구현했다. **한 서버 프로세스**로 실행한다. 임시 음성은 작업 종료/삭제 시 제거하고, 작업과 결과는 생성 후 **15분**에 만료한다. 서버가 멈추면 청소는 재시작 후 수행한다. 추론 중 이미 메모리에 읽은 음성은 연산 종료까지 남을 수 있으므로 DELETE 204는 저장 파일·결과 삭제 및 결과 재부착 차단을 의미한다. 프로세스 강제 종료형 추론 취소는 아직 없다.

앱은 결과를 로컬에 저장한 뒤 서버 작업 삭제를 시도한다. 실패하면 정리 버튼을 남긴다. 운영 로그인/토큰 발급 서비스, 관리 UI, 다중 프로세스 큐, 임상·언어별 정확도 검증은 별도 출시 작업이다. 모델/서버가 준비되지 않으면 준비되지 않음을 표시한다. [설치·API·운영 조건](../server/pronunciation_analysis/README.md).

### 플랫폼과 검증 범위

- macOS/iOS: Apple Vision OCR, Android: ML Kit 한국어·영어 OCR 연결. Windows/Linux는 직접 입력을 제공한다. OCR은 최대 10MB·2천만 화소의 PNG/JPG이며 iOS/iPadOS·Android에서는 사진 보관함 선택과 카메라 촬영 버튼을 제공한다. 사진 확인·자르기·회전 후 OCR로 이어진다. 선택 취소 시 입력한 문장을 유지하며, 가져온 임시 사본은 읽은 뒤 삭제한다. 보관함 원본은 변경하지 않는다.
- macOS 빌드, Flutter 단위·화면 테스트, 서버 API 테스트와 실제 한국어·영어 합성 음성 인식을 확인한다. iOS/Android 실기기 OCR·권한 검증 및 Windows/Linux 빌드는 별도로 필요하다.
- 기능 시험용 tiny 모델의 성공은 마비말장애 음성에 대한 임상 정확도를 뜻하지 않는다. 기존 목표 문장을 강제로 맞춘 결과나 인식 차이를 발음 점수로 표시하지 않는다.

### 긴장 안내의 적용 원칙

‘편한 자세 → 자연스러운 호흡 → 짧은 말 → 원하면 다시 듣기’가 기본이다. 상황별로 문장을 나누고 쉴 곳 정하기, 믿는 사람과 단계적으로 말하기, 점수/시간 경쟁을 줄이기 등을 안내한다. 강제 심호흡·숨 참기·목 마사지·최대 발성을 긴장 완화 과제로 추가하지 않는다. 통증·어지러움·숨참이 생기면 쉬며, 지속적인 말하기 불안은 언어재활 전문가와 정신건강 전문가의 개별 도움을 연결한다. 위 9절의 ASHA/NHS/NICE 자료를 근거로 한 보조 안내이며 효과가 검증된 개인별 치료 처방으로 표시하지 않는다.

검증 기록 (2026-10-02): Flutter 전체 회귀 179건 통과, 이후 사진 가져오기 취소를 포함한 문장 화면 4건 통과, `flutter analyze` 오류 없음, Python 서버 36건 통과, macOS debug 빌드 성공. 실제 로컬 HTTP 서버에서 한국어·영어 합성 음성의 업로드→인식→소유 녹음 연결→삭제를 확인했고 Apple Vision에서 한영 테스트 사진의 글을 추출했다. 문서 검사는 Markdown 34쌍·HTML 5쌍 및 언어 탭 독자 페이지 76개를 확인했다.

macOS 사진 선택 대기 문제를 보완하기 위해 네이티브 파일 선택 창에서 이미지 데이터를 직접 반환하도록 연결했다. 선택 취소·파일 크기 제한·미리보기 데이터 전달과 문장 화면을 합친 추가 7건 테스트가 통과했다.

**남은 수동 검증:** 현재 macOS 자동 화면 조작에서 일반 메뉴 클릭도 반영되지 않는 현상이 있어, 최신 수정본의 실제 파일 선택→사진 확인→추출문 입력란 복귀 전체 흐름은 최종 확인하지 못했다. 네이티브 Vision의 실제 한영 인식과 앱의 데이터 전달·취소 자동 테스트 통과를 전체 화면 검증 완료로 간주하지 않는다. 사용자 직접 조작으로 이 흐름을 확인하고, 재현되는 앱 문제가 있으면 추가 수정해야 한다.

### iPad 사진 입력 권한 보완

iOS의 개별 플러그인 등록 경로에 `FLTImagePickerPlugin`을 추가했다. 이전에는 플러그인이 빌드에 포함되어도 런타임에 등록되지 않아 사진 보관함·카메라 호출이 연결 오류로 끝났다. 카메라는 image_picker의 AVFoundation 권한 검사로 미결정 시 요청하고, 거부 시 앱 설정 버튼, 제한 시 스크린 타임·기기 관리 안내를 보여 준다. 사진은 PHPicker와 `requestFullMetadata: false`로 선택한 사진만 가져오므로 전체 사진 권한을 선행 조건으로 요구하지 않는다. 연결 오류는 권한 오류와 구분한다. 설정 복귀 후 사용자가 다시 누르면 OS 상태를 새로 확인하며 입력한 문장은 유지한다.

긴 OCR 결과의 진행 버튼은 본문 스크롤과 분리했다. 이미지 확인의 글 가져오기 버튼과 문장 입력의 확인 체크·저장 버튼을 하단에 고정하며, 키보드가 열리면 사용 가능한 화면 안에 배치한다. 문장 본문은 별도로 스크롤한다.

마이크 사용 시 공통 녹음 서비스가 OS 권한을 요청한다. 거부되면 현재 화면 위에 마이크 권한 안내창과 설정 열기 버튼을 보여 준다. 설정에서 허용하고 돌아온 뒤 녹음 버튼을 다시 누르면 권한을 재확인한다. 설정 복귀만으로 녹음이 자동 시작되지는 않는다. iOS 수동 등록 경로에는 PCM 녹음용 `RecordIosPlugin`도 등록한다.
