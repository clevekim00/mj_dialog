## 1. 기획 의도 재정의

이 앱의 목적은 단순한 발음 교정이나 AI 회화가 아니라, 뇌경색 이후 마비성 발음장애가 있는 사용자가 집에서도 반복적으로 말하기 연습을 하고, 보호자나 언어재활사가 경과를 확인할 수 있도록 돕는 재활 보조 도구로 보는 것이 적절하다.

따라서 제품의 중심은 "AI가 점수를 주는 앱"보다 아래에 가까워야 한다.

```text
안전한 자가 연습
→ 환자 맞춤 반복 훈련
→ 말 명료도와 의사소통 참여 개선
→ 보호자/치료사와 공유 가능한 기록
→ 치료를 대체하지 않는 보조 도구
```

## 2. 임상 배경에서 중요한 점

ASHA는 마비성 발음장애가 호흡, 발성, 조음, 공명, 운율 같은 말 산출 하위 시스템을 방해해 말 명료도와 자연스러움에 영향을 줄 수 있다고 설명한다. 또한 치료 계획은 말 운동 학습과 신경가소성 원리를 고려해야 하며, 연습량, 반복, 난이도, 피드백 방식이 중요하다.

American Stroke Association은 뇌졸중 후 마비성 발음장애가 발음, 음량, 말 속도, 억양에 영향을 줄 수 있고, 개인별 문제가 다르므로 언어치료사와 함께 개별화된 치료 프로그램을 세우는 것이 좋다고 안내한다.

NICE 뇌졸중 재활 지침은 뇌졸중 후 의사소통 어려움이 의심되면 언어치료사에게 의뢰해 상세 평가를 받아야 하고, 언어치료사가 실어증 또는 마비성 발음장애 같은 구체적 의사소통 손상에 대해 개별화된 치료를 제공해야 한다고 권고한다. 또한 가족, 보호자, 돌봄 인력이 지지적 의사소통 기술을 익히도록 코칭하는 것이 중요하다고 본다.

## 3. 현재 앱이 이미 갖춘 강점

현재 코드 기준으로 앱은 재활 보조 도구의 기반을 어느 정도 갖추고 있다.

```text
음성 기반 대화
→ ChatScreen, ChatController, SttService, TtsService

소리 내어 읽기 연습
→ PracticeScreen, PracticeNotifier, PracticeSentenceService

녹음 및 재생
→ AudioRecorderService, AudioPlayerService

연습 기록
→ PracticeHistoryService, PracticeHistoryScreen

성과 확인
→ DashboardScreen

권한 안내
→ PermissionScreen, PermissionService
```

좋은 방향은 다음과 같다.

- 텍스트 입력보다 음성 중심 UI에 가까워 실제 발화 연습과 잘 맞는다.
- 문장 읽기와 자유 발화가 둘 다 있어 정형 연습과 기능적 말하기를 함께 다룰 수 있다.
- 녹음 재생 기능이 있어 자기 발화를 다시 듣는 훈련으로 확장하기 쉽다.
- 연습 기록과 대시보드가 있어 반복 훈련을 습관화할 기반이 있다.

## 4. 현재 앱과 기획 의도 사이의 차이

현재 앱은 "발음 점수와 피드백"은 제공하지만, 뇌경색 후 마비성 발음장애 재활에 필요한 다음 요소가 아직 부족하다.

### 4.1 환자 상태 기반 초기 평가가 없음

현재 앱은 사용자의 뇌졸중 시점, 마비 부위, 동반 증상, 피로도, 의사소통 목표를 묻지 않는다. 마비성 발음장애는 유형과 중증도에 따라 호흡, 발성, 조음, 운율 문제가 다르게 나타나므로 같은 문장을 모두에게 주는 방식만으로는 맞춤 재활이 어렵다.

필요 기능:

- 첫 실행 온보딩에서 재활 목적과 현재 상태 입력
- 발병 시점, 치료 중 여부, 언어치료사 유무, 주 연습 목표 기록
- 말하기 어려움 영역 선택: 작게 말함, 느리거나 빠름, 발음이 뭉개짐, 숨이 짧음, 억양이 단조로움
- 보호자/치료사용 메모 필드

### 4.2 운동학습 기반 연습 설계가 약함

현재 문장 목록은 어려운 한국어 문장과 일상 문장 위주다. 하지만 재활에서는 초기에는 짧고 성공 가능한 목표부터 시작하고, 점차 난이도와 변동성을 조절해야 한다.

필요 기능:

- 난이도 단계: 음절, 단어, 짧은 구, 문장, 대화
- 목표 하위 시스템: 호흡, 음량, 조음, 속도, 억양
- 반복 세트: 예를 들어 한 문장 5회 반복, 휴식 후 2세트
- 피로도 체크: 시작 전/후 피로도 입력
- 자동 난이도 조절: 성공률과 피로도 기반으로 다음 과제 추천

### 4.3 점수가 임상적으로 설명되지 않음

현재 `AiResponse.pronunciationScore`는 0-100 점수 중심이다. 하지만 환자와 보호자에게는 점수 하나보다 어떤 요소가 좋아졌고 어떤 전략을 써야 하는지가 더 중요하다.

필요 기능:

- 점수의 의미 설명: "의학적 진단 점수 아님", "자가 연습 참고용"
- 하위 지표 분리: 명료도, 속도, 음량, 호흡, 조음 정확도, 운율
- 이전 자기 기록 대비 변화 표시
- 실패/무음/마이크 문제와 실제 발음 저하를 분리
- AI 피드백 신뢰도 표시: STT 신뢰도, 녹음 품질, 주변 소음

### 4.4 삼킴장애와 안전 경고가 없음

마비성 발음장애는 삼킴장애와 동반될 수 있다. 앱이 직접 삼킴을 평가해서는 안 되지만, 위험 신호와 전문 진료 안내는 필요하다.

필요 기능:

- 시작 전 안전 안내: 갑작스러운 말 변화, 삼킴 곤란, 사레, 호흡 곤란, 새 신경학적 증상이 있으면 의료진 상담
- 연습 중 중단 버튼
- 피로, 어지러움, 호흡 불편감 체크
- "이 앱은 치료/진단을 대체하지 않는다" 고지

### 4.5 보호자/치료사 참여 기능이 부족함

NICE 지침은 가족과 보호자, 돌봄 인력의 지지적 의사소통 코칭을 중요하게 본다. 현재 앱은 개인 연습 기록은 있지만, 보호자나 치료사가 목표를 설정하고 결과를 확인하는 흐름은 약하다.

필요 기능:

- 보호자 모드: 오늘 연습 여부, 피로도, 어려웠던 문장 확인
- 치료사 공유 리포트: PDF/CSV 내보내기
- 치료사 처방 문장 세트 등록
- 가족 대화 과제: 실제 생활 문장, 예/아니오 질문, 전화 상황, 병원 접수 상황
- 대화 상대 팁: 천천히 기다리기, 끊지 않기, 조용한 환경 만들기

### 4.6 기능적 의사소통 훈련이 부족함

현재 연습은 문장 읽기와 자유 읽기에 가깝다. 실제 환자에게 중요한 것은 병원, 가족, 전화, 식사, 외출 등 생활 상황에서 의사를 표현하는 것이다.

필요 기능:

- 상황별 말하기 과제: 통증 표현, 약 복용, 식사 요청, 화장실 요청, 길 묻기
- 핵심 문장 즐겨찾기
- AAC 보조판: 자주 쓰는 단어/그림/문장 버튼
- 첫 글자 힌트 또는 키워드 카드
- 조용한 환경 만들기, 얼굴 보고 말하기 같은 보상 전략 안내

## 5. 우선순위별 개선 제안

### P0. 안전성과 제품 경계 설정

가장 먼저 해야 할 일은 이 앱이 진단/치료 대체물이 아니라 재활 보조 도구임을 명확히 하는 것이다.

구현 제안:

```text
lib/features/onboarding/
→ 재활 목적 안내
→ 응급/위험 신호 안내
→ 치료사 상담 권장
→ 개인정보/녹음 저장 동의
```

UI 문구 예:

```text
이 앱은 뇌졸중 후 말하기 연습을 돕는 보조 도구입니다.
진단이나 치료를 대체하지 않으며, 연습 계획은 언어재활사와 상의해 조정하는 것이 좋습니다.
갑작스러운 말 변화, 삼킴 곤란, 호흡 불편, 새 마비 증상이 있으면 즉시 의료진에게 문의하세요.
```

### P0. 재활 맞춤 초기 평가

현재 `StartupResolver` 다음에 바로 히스토리 화면으로 가는 구조다. 기획 의도를 반영하려면 최초 1회 프로필/목표 설정이 필요하다.

필요 데이터:

- 발병 후 기간: 1개월 미만, 1-3개월, 3-6개월, 6개월 이상
- 현재 치료 여부
- 주된 어려움: 발음, 음량, 속도, 숨, 억양, 피로
- 연습 가능 시간: 5분, 10분, 15분
- 보호자 동반 여부
- 오늘의 목표: 또렷하게 말하기, 천천히 말하기, 크게 말하기, 짧은 문장 완성

### P0. 연습 세션 구조화

현재는 사용자가 녹음하고 평가받는 단일 루프다. 재활 목적이라면 세션 단위가 필요하다.

권장 세션 구조:

```text
준비
→ 오늘 컨디션/피로도 체크

워밍업
→ 호흡 또는 짧은 모음 발성

핵심 연습
→ 개인 목표 문장 3-5개
→ 각 문장 3회 반복

기능적 말하기
→ 실제 생활 상황 문장 1개

마무리
→ 오늘 변화, 어려웠던 점, 다음 과제 표시
```

### P1. 점수 체계 재설계

현재의 단일 점수는 유지하되, 재활 앱에서는 하위 지표를 분리해야 한다.

추천 지표:

```text
말 명료도
→ STT 결과와 목표 문장 유사도, 음절 누락/대체 추정

말 속도
→ 녹음 길이와 문장 길이 기반

음량 안정성
→ 녹음 amplitude 분석 기반

호흡 지속
→ 한 번에 말한 구간 길이, 중간 끊김 수

운율/억양
→ 현재는 AI 피드백 텍스트 수준으로 시작, 이후 pitch 추출 검토
```

주의:

```text
의학적 중증도 점수처럼 표현하지 말 것
환자 간 비교보다 자기 이전 기록 대비 변화 중심으로 보여줄 것
```

### P1. 개인화 문장 라이브러리

현재 `PracticeSentenceService`는 어려운 발음 문장과 일상 문장을 제공한다. 마비성 발음장애 재활에서는 어려운 말장난 문장보다 기능적이고 개인에게 중요한 문장이 더 우선이다.

추가할 문장 카테고리:

- 병원: "통증이 있어요", "물을 마시고 싶어요", "어지러워요"
- 집: "도와주세요", "화장실에 가고 싶어요", "천천히 말할게요"
- 가족: "오늘 기분이 좋아요", "조금 쉬고 싶어요"
- 전화: "다시 말씀해 주세요", "천천히 말하겠습니다"
- 감정: "답답해요", "고마워요", "괜찮아요"

### P1. 보호자/치료사 공유

현재 공유 기능은 녹음 파일 공유에 가깝다. 보호자/치료사에게 필요한 것은 요약 리포트다.

리포트에 포함할 항목:

- 기간별 연습 횟수
- 평균 점수보다 "연습 지속성"과 "목표별 변화"
- 자주 실패한 문장/음절
- 피로도 변화
- 녹음 샘플 링크 또는 파일
- 환자 메모와 보호자 메모

### P1. 접근성 강화

뇌경색 이후에는 편마비, 시야 문제, 인지 피로, 손 조작 어려움이 동반될 수 있다.

필요 개선:

- 큰 버튼 모드
- 한 손 조작 모드
- 글자 크게 보기
- 긴 설명 줄이기
- 색만으로 점수 구분하지 않기
- 음성 안내
- 보호자가 대신 조작하기 쉬운 화면

### P2. AI/백엔드 경로 명확화

현재 `evaluateAudio()`는 실제 오디오 분석이 아니라 텍스트 기반 fallback에 가깝다. 기획 의도상 이 부분은 명확히 결정해야 한다.

선택지:

```text
MVP
→ STT 텍스트 기반 평가라고 명시
→ 녹음 품질, 음량, 길이 같은 로컬 음향 지표만 추가

고도화
→ 백엔드로 오디오 파일 전송
→ 음성 특징 추출
→ 치료사 검수 데이터로 평가 모델 개선
```

## 6. 기능 적합도 매트릭스

| 기능 영역 | 현재 상태 | 재활 목적 적합도 | 개선 필요 |
|---|---:|---:|---|
| 음성 입력/STT | 있음 | 중간 | STT 실패와 발음 문제 구분 필요 |
| 녹음/재생 | 있음 | 높음 | 자기 비교, 치료사 공유 강화 |
| 문장 읽기 | 있음 | 중간 | 난이도/목표별 문장 필요 |
| 자유 발화 | 있음 | 중간 | 상황 기반 과제로 확장 |
| 대시보드 | 있음 | 중간 | 점수보다 변화/지속성 중심 필요 |
| 안전 안내 | 일부 권한 안내만 있음 | 낮음 | 의료 안전 고지 필요 |
| 초기 평가 | 없음 | 낮음 | 환자 상태/목표 설정 필요 |
| 보호자/치료사 모드 | 없음 | 낮음 | 리포트/처방/메모 필요 |
| AAC/보완 의사소통 | 없음 | 낮음 | 심한 발화 어려움 대응 필요 |
| 개인정보/동의 | 권한 중심 | 낮음 | 녹음/건강정보 동의 필요 |

## 7. 추천 개발 순서

### 1단계: 재활 앱으로서의 안전한 틀 만들기

- 의료 고지/응급 신호 안내 추가
- 초기 프로필과 목표 설정 추가
- 테스트용 문구를 "발음 교정"에서 "재활 보조"로 정리

### 2단계: 연습 루틴 구조화

- 5분/10분 연습 세션 추가
- 피로도 체크 추가
- 문장 난이도와 목표 영역 추가
- 반복 횟수와 휴식 타이머 추가

### 3단계: 피드백 고도화

- 단일 점수에서 하위 지표로 확장
- STT 신뢰도와 녹음 품질 표시
- 환자별 이전 기록 대비 변화 표시

### 4단계: 보호자/치료사 연동

- 주간 리포트 생성
- 치료사 처방 문장 세트
- 보호자 메모
- 공유 가능한 PDF/CSV

### 5단계: 기능적 의사소통과 AAC

- 생활 상황별 말하기 과제
- 자주 쓰는 문장 버튼
- 첫 글자 힌트, 키워드 카드
- 말하기 어려운 날을 위한 대체 의사소통 화면

## 8. 바로 구현하면 좋은 작은 작업

코드 변경 부담이 낮고 효과가 큰 항목은 다음과 같다.

```text
README.md
→ "뇌경색 후 마비성 발음장애 재활 보조" 목적 명시
→ 의료 고지 추가

PracticeSentenceService
→ 병원/집/가족/전화 상황 문장 카테고리 추가

PracticeProgress
→ fatigueBefore, fatigueAfter, sessionGoal 필드 추가

DashboardScreen
→ 평균 점수 외에 연습 지속일, 최근 7일 수행률 표시

PracticeHistoryService
→ 메모 필드와 세션 목표 저장

PermissionScreen 또는 OnboardingScreen
→ 녹음/건강정보 저장 동의와 응급 신호 안내 추가
```

## 9. 기획 방향 결론

현재 앱은 음성 입력, 읽기 연습, 녹음 재생, 기록, 대시보드라는 좋은 뼈대를 이미 갖고 있다. 하지만 뇌경색 후 마비성 발음장애 환자의 재활을 돕기 위한 앱이라면 "AI가 발음을 채점하는 기능"보다 "안전하고 개인화된 반복 연습 루틴"과 "치료사/보호자와 공유 가능한 경과 기록"이 더 중요하다.

다음 제품 목표는 이렇게 잡는 것이 좋다.

```text
환자가 매일 짧게 연습하고,
보호자와 치료사가 변화를 이해하며,
앱은 진단자가 아니라 안전한 연습 동반자로 남는다.
```
